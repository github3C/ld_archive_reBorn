我当时拿到的版本，是从第三位维护者那里下载的 ZIP 包。他的修改内容甚至都没有提交到 Git。从上面的截图也可以看出来，提交历史里第一个中文提交，也就是“转为中文”的提交，是我把他的修改整理后提交进去的。

二、当时我能看到的来源链路

根据当时 ZIP 包里的 Git 历史和社群帖子，项目来源链路大致如下。

第一位作者

第一位作者更新了 11 个提交，并发布了这个话题：

【一键CPA认证+gpt注册+上传】CPA自动注册+OAuth认证的Chrome插件发布！！！！ - 开发调优 / 开发调优, Lv2 - LINUX DO

这个话题里没有任何远程仓库地址，也没有仓库协议或 LICENSE。

第二位维护者 Jimmy

之后是第二位佬友继续修改，更新了 5 个提交，Git 信息中作者为 Jimmy，并发布了这个话题：

基于chrome插件的codex注册机修改全自动优化，新增支持inbucket - 开发调优 / 开发调优, Lv2 - LINUX DO

这时候同样没有任何远程仓库地址，也没有仓库协议或 LICENSE。

第三位维护者

接下来是第三位佬友。他是在前面基础上直接修改后开了一个话题：

浏览器插件codex注册 在大佬的基础上修改 - 开发调优 / 开发调优, Lv2 - LINUX DO

他没有提交 Git，所以我拿到 ZIP 后，提交历史里第一个中文提交，就是我把他的修改提交进去的。

三、我发布第一版时已经写了来源

我秉承第三位佬友说的“取之于佬，用之于佬”的精神，新开了我自己的话题。

第一版内容，开头就直接引用了三位维护者的话题来源，下面放的是 ZIP 压缩包。也就是说，我没有删除任何一位佬友的项目来源。

四、为什么后来创建 GitHub 仓库

后面有人说，让我开一个仓库，这样大家一起维护更新更方便。我觉得确实是这样，就创建了当前仓库，并在话题第二版内容里添加了 GitHub 仓库地址。

当时我不是很了解开源协议这个东西。我问了 AI，我也不介意大家任何人使用，因为我本来也只是二开，不是原创，然后AI就推荐我选择了 Apache-2.0。今天才知道了原作者的仓库后，所以已经改为 MIT，并补充了原作者来源和致谢说明。

五、关于 QQ 群、官网和服务入口

后来我一直持续更新维护。我的 GitHub 地址里也一直直接使用该话题地址作为来源说明。

开发了一周左右后，我发现大家交流特别麻烦，有些问题在话题下面根本无法解决。于是我修改版本内容，询问是否可以添加 QQ 交流群。不过当时大家还是一直在问问题，也没人回答。

又过了几天，我想着这是开源软件，而且仓库里挂的还是 L 站话题地址，应该没什么问题；同时大家交流确实麻烦，于是就创建了交流群。QQ群创建后，大家的问题明显可以更快得到解决。在这期间我也认识了很多佬友，我觉得这确实挺不错的。

后来帖子突然被举报封禁了。我当时不知道怎么解决，又发了一个话题，结果发现也没有了，应该是被三级佬删除了。后面我看到始皇置顶的帖子里说可以 @ 管理员，我也去 @ 了，但没有反应。

image1026×898 67.4 KB

那段时间我也在高强度维护项目，号池直接 429，群里的群友们就让我开贡献。后面我开了一个贡献入口，又想着既然这么多人问问题，不如再做一个使用教程，于是第一版官网就做出来了，用得久的佬友应该知道。

由于 L 站话题被删除，原来的地址也没什么用了，我就把地址更换成了我的贡献页面。后面使用教程越来越多，我又直接重构了页面，形成了现在的官网。

这时候首页比较空，我就想着加个广告：一方面可以继续维护项目，另一方面也可以赚点外快，我觉的以我更新维护项目速度和时间来说（可以查看git变更记录），拿个广告费是没有什么问题的，就当是我维护项目的支持了。我并没有要求大家使用这个项目就必须交钱，项目一直是免费使用的。我当时觉得这应该是对双方都有利，我更有动力维护项目，大家也能用上更好的功能。

六、关于原作者 GitHub 仓库和协议

直到今天（2026 年 5 月 5 日），有人给我发消息，说三级区有人说我没有尊重原创。

但我的项目最开始就是在 L 站发的，也明确标明了三位维护者来源，从来没有删除过。当时大家发布的也都是 ZIP 文件，没有远程仓库地址信息，也没有协议文件。

等 L 站删除我帖子时，我都已经维护仓库半个月左右了。那时候每天忙得要死，白天要上班，晚上还要维护仓库，天天三四点才睡，确实没有心思想那么多。只能说我当时 @ 了管理者，没反应也就没反应了；而且 QQ 群交流确实方便，这又和 L 站要求冲突，所以就没有再发了。

也是今天别人给我发那个帖子，我让他在话题底下找了一下，才知道原作者后面也发布了 GitHub 仓库：

https://github.com/whwh1233/StepFlow-Duck

我是真的不知情。原仓库作者后面发布了仓库，但也没有更新到原来的话题里。我这一个月都是这样，每天熬夜维护到三四点，一到周末就可能开发新功能到通宵，简直忙着晕头转向的，也没有再去想着说L站把我帖子删除了，我还能想着说去把这个 ZIP 文件来源追到 GitHub 上。

不过现在我已经知道了，也已经在当前 GitHub 仓库中补充了原作者仓库地址、来源说明、原作者署名和致谢，并将仓库协议改为了 MIT。
